1   Why Oscillators Matter

The harmonic oscillator is the most important system in all of physics. That's not hyperbole. Here is why:

  • Every stable equilibrium looks like a harmonic oscillator for small displacements. (Taylor section 5.1 proves this.)
  • Springs, pendulums, vibrating strings, LC circuits, molecular bonds, even quantum fields all are oscillators or collections of oscillators.
  • Understanding how to simulate an oscillator correctly is the gateway to simulating everything

And as you're about to discover, oscillators are the system that most ruthlessly punishes a bad numerical integrator.

2   The Simple Harmonic Oscillator

2.1   The physics

A mass m attached to a spring with spring constant k, displaced from equilibrium:

F = −kx    →    a = −(k/m)x = −ω₀²x

where ω₀ = √(k/m) is the natural frequency. The exact solution is:

x(t) = A cos(ω₀t + φ)

The amplitude A and phase φ depend on initial conditions. The period T = 2π/ω₀ is independent of amplitude, a hallmark of the harmonic oscillator.

2.2   Setting up the simulation

The state vector is [x, v]. The force function is one line:

import numpy as np
import matplotlib.pyplot as plt

# Parameters
k = 1.0     # spring constant (N/m)
m = 1.0     # mass (kg)
omega0 = np.sqrt(k / m)   # natural frequency
T = 2 * np.pi / omega0      # period

# Initial conditions
x0 = 1.0    # initial displacement (m)
v0 = 0.0    # released from rest

# Exact solution for comparison
def exact_x(t):
    return x0 * np.cos(omega0 * t)

def exact_v(t):
    return -x0 * omega0 * np.sin(omega0 * t)

2.3   Euler vs. Euler-Cromer: the moment of truth

Let's run both methods for 10 oscillation periods and see what happens:

def simulate_sho(method, dt, n_periods=10):
    """Simulate SHO. Returns t, x, v, E arrays."""
    t_max = n_periods * T
    x, v = x0, v0
    ts, xs, vs, Es = [0], [x], [v], [0.5*k*x**2 + 0.5*m*v**2]
    t = 0.0

    while t < t_max:
        a = -(k / m) * x

        if method == 'euler':
            x_new = x + v * dt
            v_new = v + a * dt
            x, v = x_new, v_new
        elif method == 'euler-cromer':
            v = v + a * dt       # velocity first
            x = x + v * dt       # then position with new v

        t += dt
        E = 0.5 * k * x**2 + 0.5 * m * v**2
        ts.append(t); xs.append(x); vs.append(v); Es.append(E)

    return np.array(ts), np.array(xs), np.array(vs), np.array(Es)

# Run both with dt = T/50 (moderately coarse)
dt = T / 50
t_e, x_e, v_e, E_e = simulate_sho('euler', dt)
t_ec, x_ec, v_ec, E_ec = simulate_sho('euler-cromer', dt)
t_exact = np.linspace(0, 10*T, 2000)

# ─── Plot: x(t) comparison ────────────────────────────────────
fig, axes = plt.subplots(3, 1, figsize=(12, 10), sharex=True)

axes[0].plot(t_exact, exact_x(t_exact), 'k-', alpha=0.4, label='Exact')
axes[0].plot(t_e, x_e, 'r-', alpha=0.8, label='Euler')
axes[0].set_ylabel('x (m)')
axes[0].set_title('Standard Euler — Position vs. Time')
axes[0].legend()
axes[0].grid(True, alpha=0.3)

axes[1].plot(t_exact, exact_x(t_exact), 'k-', alpha=0.4, label='Exact')
axes[1].plot(t_ec, x_ec, 'b-', alpha=0.8, label='Euler-Cromer')
axes[1].set_ylabel('x (m)')
axes[1].set_title('Euler-Cromer — Position vs. Time')
axes[1].legend()
axes[1].grid(True, alpha=0.3)

axes[2].plot(t_e, E_e, 'r-', label='Euler')
axes[2].plot(t_ec, E_ec, 'b-', label='Euler-Cromer')
axes[2].axhline(y=E_e[0], color='k', linestyle='--', alpha=0.3, label='True energy')
axes[2].set_xlabel('Time (s)')
axes[2].set_ylabel('Total Energy (J)')
axes[2].set_title('Energy Comparison')
axes[2].legend()
axes[2].grid(True, alpha=0.3)

plt.tight_layout()
plt.show()
⚠️ What you should see: The Euler solution spirals outward, its amplitude grows with every cycle. After 10 periods, the oscillation is noticeably larger than it should be. The energy plot confirms it: total energy climbs steadily. The Euler-Cromer solution, by contrast, maintains a stable amplitude and its energy oscillates slightly around the true value but never drifts.
💡 Key Idea: For oscillatory systems, the standard Euler method is not just inaccurate, it is qualitatively wrong. It predicts a system that gains energy over time, which violates physics. Euler-Cromer, with one line of code changed, gets the qualitative behavior right. This is why integrator choice matters, and why we don't just use the "simplest" method.

3   Phase Space: A New Way to See Dynamics

3.1   What is phase space?

Instead of plotting x vs. t (position over time), plot x vs. v (position vs. velocity). This is a phase-space plot, and it reveals the structure of the motion in a completely different way.

For the simple harmonic oscillator, the exact phase-space trajectory is an ellipse:

(x/A)² + (v/(Aω₀))² = 1

The system traces this ellipse forever, going clockwise. It never spirals in or out , the ellipse has a fixed size determined by the total energy.

3.2   Phase-space plots as a diagnostic

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 5))

# Euler phase portrait
ax1.plot(x_e, v_e, 'r-', alpha=0.7, linewidth=0.5)
ax1.plot(x_e[0], v_e[0], 'ko', markersize=8, label='Start')
ax1.set_xlabel('x (m)'); ax1.set_ylabel('v (m/s)')
ax1.set_title('Euler — Phase Space')
ax1.set_aspect('equal')
ax1.legend()
ax1.grid(True, alpha=0.3)

# Euler-Cromer phase portrait
ax2.plot(x_ec, v_ec, 'b-', alpha=0.7, linewidth=0.5)
ax2.plot(x_ec[0], v_ec[0], 'ko', markersize=8, label='Start')
ax2.set_xlabel('x (m)'); ax2.set_ylabel('v (m/s)')
ax2.set_title('Euler-Cromer — Phase Space')
ax2.set_aspect('equal')
ax2.legend()
ax2.grid(True, alpha=0.3)

plt.tight_layout()
plt.show()
💡 Key Idea: In phase space, the Euler method's energy growth is instantly visible, the trajectory spirals outward. Euler-Cromer produces a closed (or very nearly closed) curve. A perfect integrator would trace a single ellipse over and over. The phase portrait is often more revealing than an x-vs-t plot because you can see the structure of the error at a glance.
🧪 Try it: Run the Euler-Cromer simulation with dt = T/20 (coarse) and dt = T/200 (fine). Compare the phase-space plots. You should see that the coarser Δt produces a wider "band" around the ellipse (the slightly different nearby energy that Euler-Cromer conserves), while the finer Δt produces a thinner band. The band width is proportional to Δt.

3.3   Reading a phase portrait

Phase-space plots encode a lot of information. Here's how to read them:

Summary of features and their meanings in the system's motion characteristics
FeatureWhat It Means
Closed curve (ellipse, circle)Periodic motion, the system repeats
Outward spiralEnergy increasing, numerical error or driven system
Inward spiralEnergy decreasing, damping or dissipation
Point (the origin)Stable equilibrium
Larger ellipseHigher energy (larger amplitude)
Direction (clockwise for SHO)Determined by the signs of dx/dt and dv/dt

4   Damped Oscillations

4.1   The physics

Real oscillators lose energy to friction, air resistance, or internal heating. The simplest damping model is a force proportional to velocity (linear drag):

F = −kx − bv

where b is the damping coefficient. Taylor section 5.4 shows this leads to three regimes depending on the ratio of damping to natural frequency. Define β = b/(2m):

Summary of damping regimes and their effects on system behavior
RegimeConditionBehavior
Underdampedβ < ω₀Oscillates with exponentially decaying amplitude
Critically dampedβ = ω₀Returns to equilibrium as fast as possible without oscillating
Overdampedβ > ω₀Returns to equilibrium slowly, no oscillation

4.2   In code

def simulate_damped_sho(beta, dt=0.02, t_max=30.0):
    """Simulate damped SHO with Euler-Cromer.
    beta = b/(2m) is the damping parameter.
    """
    x, v = x0, v0
    b_damp = 2 * m * beta  # recover b from beta
    ts, xs, vs = [0], [x], [v]
    t = 0.0

    while t < t_max:
        # Force: spring + linear damping
        a = -(k / m) * x - (b_damp / m) * v

        # Euler-Cromer
        v = v + a * dt
        x = x + v * dt
        t += dt
        ts.append(t); xs.append(x); vs.append(v)

    return np.array(ts), np.array(xs), np.array(vs)

# ─── Compare three damping regimes ────────────────────────────
fig, axes = plt.subplots(2, 1, figsize=(12, 8))

regimes = [
    (0.1,  'Underdamped (β = 0.1)',   'b'),
    (omega0, 'Critically damped (β = ω₀)', 'g'),
    (3.0,  'Overdamped (β = 3.0)',     'r'),
]

for beta, label, color in regimes:
    t, x, v = simulate_damped_sho(beta)
    axes[0].plot(t, x, color=color, label=label, linewidth=1.5)
    axes[1].plot(x, v, color=color, label=label, linewidth=0.8, alpha=0.8)

# x(t) plot
axes[0].set_xlabel('Time (s)'); axes[0].set_ylabel('x (m)')
axes[0].set_title('Damped Oscillator: x(t) for Three Regimes')
axes[0].legend(); axes[0].grid(True, alpha=0.3)
axes[0].axhline(y=0, color='k', alpha=0.2)

# Phase portrait
axes[1].set_xlabel('x (m)'); axes[1].set_ylabel('v (m/s)')
axes[1].set_title('Damped Oscillator: Phase Space')
axes[1].legend(); axes[1].grid(True, alpha=0.3)
axes[1].plot(0, 0, 'k+', markersize=15, markeredgewidth=2)  # equilibrium point

plt.tight_layout()
plt.show()
🔬 Physics connection: In phase space, damping turns the ellipse into an inward spiral converging on the origin (equilibrium). The underdamped case spirals inward; the overdamped case crawls along the x-axis toward zero. The critically damped case reaches the origin fastest. These are qualitatively different behaviors produced by a single parameter, this is why physicists care about phase portraits.

5   Driven Oscillations and Resonance

5.1   The physics

Now add a periodic driving force:

F = −kx − bv + F₀ cos(ωd t)

where F₀ is the driving amplitude and ωd is the driving frequency. Taylor sections 5.5 - 5.6 show that after transients die out, the system oscillates at the driving frequency ωd, with an amplitude that depends on how close ωd is to ω₀.

When ωd ≈ ω₀ (and damping is small), the amplitude becomes very large. This is resonance, the most dramatic phenomenon in oscillatory physics.

5.2   In code

def simulate_driven_sho(omega_d, F0, beta, dt=0.02, t_max=80.0):
    """Simulate driven, damped SHO with Euler-Cromer."""
    x, v = 0.0, 0.0  # start at rest — watch transients build
    b_damp = 2 * m * beta
    ts, xs = [0], [x]
    t = 0.0

    while t < t_max:
        # Force: spring + damping + driving
        a = -(k/m)*x - (b_damp/m)*v + (F0/m)*np.cos(omega_d * t)

        v = v + a * dt
        x = x + v * dt
        t += dt
        ts.append(t); xs.append(x)

    return np.array(ts), np.array(xs)

5.3   Sweeping the driving frequency

The real power of numerical methods: scan across many driving frequencies and measure the steady-state amplitude at each one. This produces a resonance curve.

beta = 0.1   # light damping
F0 = 1.0     # driving amplitude

omega_values = np.linspace(0.2, 2.0, 80)
amplitudes = []

for omega_d in omega_values:
    t, x = simulate_driven_sho(omega_d, F0, beta, dt=0.01, t_max=150.0)
    # Steady-state amplitude: max of x in the last 20% of the simulation
    n_start = int(0.8 * len(x))
    amp = np.max(np.abs(x[n_start:]))
    amplitudes.append(amp)

# Analytical resonance curve for comparison
omega_exact = np.linspace(0.2, 2.0, 500)
b_val = 2 * m * beta
A_exact = (F0/m) / np.sqrt((omega0**2 - omega_exact**2)**2 + (2*beta*omega_exact)**2)

plt.figure(figsize=(10, 6))
plt.plot(omega_values, amplitudes, 'ro', markersize=5, label='Simulation')
plt.plot(omega_exact, A_exact, 'b-', linewidth=2, label='Analytical', alpha=0.7)
plt.axvline(x=omega0, color='gray', linestyle='--', alpha=0.5, label='ω₀')
plt.xlabel('Driving Frequency ω_d (rad/s)', fontsize=12)
plt.ylabel('Steady-State Amplitude (m)', fontsize=12)
plt.title('Resonance Curve: Driven Damped Oscillator', fontsize=14)
plt.legend(fontsize=11)
plt.grid(True, alpha=0.3)
plt.tight_layout()
plt.show()
💡 Key Idea: You just computed an entire resonance curve, something that would be a painful analytical exercise, by running a loop. This is the essence of computational physics: use the computer to explore parameter space systematically. You can answer questions like "what happens if I double the damping?" or "how does the peak shift if the spring constant changes?" in seconds.

6   The Nonlinear Pendulum: Beyond Small Angles

The simple pendulum equation is:

α = −(g/L) sin(θ)

If you approximate sin(θ) ≈ θ (small angles), this reduces to the SHO. But for large angles, the full sin(θ) makes the equation nonlinear, and there's no closed-form solution. This is another place where numerical methods shine.

def simulate_pendulum(theta0_deg, dt=0.01, n_periods=5):
    """Simulate nonlinear pendulum with Euler-Cromer."""
    g_val = 9.81
    L = 1.0   # length (m)
    omega0_pend = np.sqrt(g_val / L)
    T_small = 2 * np.pi / omega0_pend  # small-angle period

    theta = np.radians(theta0_deg)
    omega_val = 0.0
    ts, thetas, omegas = [0], [theta], [omega_val]
    t = 0.0

    while t < n_periods * T_small:
        alpha = -(g_val / L) * np.sin(theta)  # nonlinear!
        omega_val += alpha * dt
        theta += omega_val * dt
        t += dt
        ts.append(t); thetas.append(theta); omegas.append(omega_val)

    return np.array(ts), np.array(thetas), np.array(omegas)

# Compare small and large angle
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(14, 5))

for angle, color, label in [(10, 'b', '10°'), (45, 'g', '45°'), (90, 'r', '90°'), (170, 'purple', '170°')]:
    t, theta, omega_val = simulate_pendulum(angle)
    ax1.plot(t, np.degrees(theta), color=color, label=label)
    ax2.plot(theta, omega_val, color=color, label=label, linewidth=0.8)

ax1.set_xlabel('Time (s)'); ax1.set_ylabel('θ (degrees)')
ax1.set_title('Nonlinear Pendulum: θ(t)')
ax1.legend(); ax1.grid(True, alpha=0.3)

ax2.set_xlabel('θ (rad)'); ax2.set_ylabel('ω (rad/s)')
ax2.set_title('Nonlinear Pendulum: Phase Space')
ax2.legend(); ax2.grid(True, alpha=0.3)

plt.tight_layout()
plt.show()
🔬 Physics connection: Notice two things in the x(t) plot: (1) the period gets longer for larger amplitudes — the SHO's amplitude-independent period is an approximation that breaks down; (2) for 170°, the motion is visibly non-sinusoidal. In phase space, the small-angle trajectories are nearly circular, while the large-angle trajectories are distorted. At 180° (the separatrix), the pendulum would balance precariously, above that energy, it swings over the top.
